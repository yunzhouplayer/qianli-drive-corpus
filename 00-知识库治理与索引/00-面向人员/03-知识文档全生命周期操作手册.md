# 知识文档全生命周期操作手册

> 本手册将创建、命名、元数据、评审、发布、维护、暂停、归档、清理和纠错串成一条操作链。机器字段、类型、必填条件和状态约束以[元数据 Schema](../01-面向AI/schemas/02-metadata-schema.yaml)为唯一来源。

## 一、生命周期与责任

|阶段|责任人|关键动作|
|---|---|---|
|创建|文档负责人|确定归属、填写内容和元数据、设置初始权限|
|评审|文档负责人、内容审批人|检查准确性、适用范围、权限和安全等级|
|发布|内容审批人、空间管理员|设置正式和有效状态，按需发起索引准入|
|维护|文档负责人|按复审周期更新并处理纠错反馈|
|暂停|空间管理员、安全审核人|停止引用、控制风险并发起复审|
|归档|空间管理员|标记过期或废弃，移交长期成果并移除生产索引|
|清理|空间管理员|按保留期限审批并清理源文档和派生数据|

## 二、创建与查重

1. 确认内容应归属的责任空间和目录。
2. 搜索是否已有同主题权威文档；已有时优先更新或引用，不复制正文另建权威版本。
3. 确认负责人、审批人、适用范围和预期复审周期。
4. 按本手册命名文档，并按[AI 友好内容写作规范](./05-AI友好内容写作规范.md)组织正文。
5. 填写结构化元数据，根据[权限与安全规范](./04-权限与安全规范.md)设置初始权限和安全等级。
6. 可调用 [`prepare-knowledge-document`](../02-Skills/prepare-knowledge-document/SKILL.md)整理候选元数据和正文缺口；该技能不代表准入审批。

## 三、命名规则

- 标题应简洁、稳定，直接说明文档主题。
- 文档类型、文档版本、适用系统版本和生效时间放入元数据，不在标题中重复维护。
- 长期有效文档标题不写日期；事件型文档使用 `YYYY-MM-DD 文档主题`。
- 不使用“最新版”“最终版”“终极版”等无法校验的描述。
- 同一主题不通过复制并改名生成多个权威版本。
- 平台如需显示分类前缀，应根据元数据中的文档类型自动生成，不要求作者手工维护。

## 四、元数据填写

优先使用飞书知识库的属性字段或结构化表单；平台不支持时才使用文档头部元数据模板。不得自行恢复已废弃的自由标签或把准备记录塞入正文头部。

- 系统生成字段不得人工覆盖，包括文档 ID、创建时间和更新时间。
- `space_id` 和 `directory_id` 使用[知识库机器蓝图](../01-面向AI/01-knowledge-structure.yaml)中的稳定 ID，不直接填写中文显示名称或物理路径。
- 业务域、系统平台、文档类型、安全等级和保留期限使用受控字典，不创建自由标签。
- 摘要写清主题、核心结论和用途，不复制标题。
- 适用与不适用范围必须明确角色、城市、系统版本、环境或其他边界。
- 正式权威文档必须关联主题 ID、内容审批人、生效时间和复审日期。
- 废弃文档必须填写替代文档或废弃原因。

`允许建立索引`、`允许回答引用`和`允许模型训练`是三个独立字段，默认均为否。任一字段为“是”都不能绕过用户 ACL、安全等级、权威状态和有效状态要求。

首批试点已登记“测试与质量”业务域和“飞书知识库”来源系统。系统与平台、保留期限仍须由责任人确认具体值；不得以自由文本绕过空字典。当前状态见[受控字典说明](../01-面向AI/vocabularies/README.md)，空白格式见[元数据模板](./11-模板/01-元数据模板.md)。

## 五、评审、发布与准入

1. 文档负责人完成自检后，将权威状态改为“评审中”。
2. 内容审批人确认内容、适用范围和生效时间；敏感内容增加安全审核。
3. 评审通过后，将权威状态改为“正式”，有效状态按生效时间设置。
4. 正式文档默认只读，文档负责人和维护团队保留受控编辑权限。
5. 需要供 Agent 使用时，按[索引准入与同步规范](../01-面向AI/04-索引准入与同步规范.md)单独审批。
6. 提交管理员前，调用 [`review-knowledge-admission`](../02-Skills/review-knowledge-admission/SKILL.md)独立审查；管理员确认和业务审批不得由任何 Agent 代替。

当前处于治理验证模式时，审查结论最高为“治理验证通过”，不得执行真实生产索引或宣称文档已经生产入库。

## 六、维护、修订与纠错

- 已经在飞书正式创建的正文只在飞书中受控修改；Git 中的治理正文提案只有通过三方比较和管理员确认后才能发布，不得自动覆盖。
- 重大内容变更须更新文档版本、修订记录、更新时间和复审日期，并重新评审。
- 发现错误或风险时立即暂停 Agent 引用，再修订、废弃或升级；使用[知识纠错记录模板](./11-模板/03-知识纠错记录模板.md)留痕。
- 每月检查命名、元数据完整性、目录归属、字典取值、内容时效、权威与有效状态、权限合理性、AI 权限和负责人有效性。
- Agent 质量指标和评测要求见[检索与回答评测规范](../01-面向AI/08-检索与回答评测规范.md)。

## 七、复审周期

- 制度、流程和 SOP 建议每 6 个月复审，组织、流程或合规变化后立即复审。
- 接口文档和技术方案随版本发布复审，最长不超过 3 个月。
- 项目型 PRD、测试方案和测试报告在项目结束后归档，发生变更时即时更新。
- 会议纪要、周报和月报用于追溯，默认归档，不作为长期权威依据。
- 运营规则、调度策略和数据质量规则建议每季度复审，规则或口径变化后立即复审。
- 合规材料以法规、政策和准入要求变化为即时复审触发条件。

## 八、暂停、归档与清理

- 错误或存在风险的正式文档先暂停引用，再修订或废弃。
- 项目结束后 30 天内完成归档和长期成果移交；过程资料归档只读。
- 长期有效的制度、业务规则、方案、接口和 SOP 转移到责任空间；协作空间保留过程记录及正式成果链接。
- 废弃前填写替代文档或废弃原因，并触发索引清理。
- 保留期限从经确认的受控字典选择；专业材料服从公司制度和法律法规。
- 归档、权限收紧、暂停、废弃和删除必须同步触发索引及派生数据处理。

## 九、发布前检查

- [ ] 已查重并确认唯一权威来源。
- [ ] 标题、正文结构和元数据符合规范。
- [ ] 负责人、审批人、适用范围、安全等级和复审日期完整。
- [ ] 权限遵循最小必要原则，未包含禁止原始入库内容。
- [ ] AI 三项权限分别确认，未把索引许可等同于引用或训练许可。
- [ ] 内容审批、安全审批和独立准入审查已按条件完成。
- [ ] 异常、纠错、替代、归档和清理路径可执行并可追溯。
