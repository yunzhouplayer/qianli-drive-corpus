# 2026-08-13 飞书知识库目录导入权限身份诊断报告

## 1. 结论

飞书知识库目录导入器的认证方式、节点读取、子节点枚举和节点创建接口使用正确。首次诊断识别出节点枚举和节点创建权限只授予用户身份；修正授权并完成应用侧发布后，五项应用身份能力复测全部通过，真实导入门禁解除。

应用通过 `tenant_access_token` 调用，因此需要租户级应用身份权限。首次租户授权状态显示，节点枚举和节点创建权限只授予用户身份；复测时两项权限均已对应用身份生效。知识库页面给应用配置的阅读或编辑权限是资源访问控制，不能替代开放平台 API 的应用身份权限。

两次诊断都只执行认证和权限状态查询，未发送节点创建、文档编辑、移动或删除请求。

## 4. 实际授权状态

|导入能力|可接受权限|应用身份|用户身份|判定|
|---|---|---:|---:|---|
|读取节点|`wiki:node:read` 或等效宽权限|已授权|已授权|通过|
|枚举子节点|`wiki:node:retrieve` 或等效宽权限|未授权|已授权|身份不匹配|
|创建节点|`wiki:node:create` 或等效宽权限|未授权|已授权|身份不匹配|
|读取新版文档|`docx:document:readonly` 或等效宽权限|已授权|已授权|通过|
|编辑新版文档|`docx:document:write_only` 或等效宽权限|已授权|已授权|通过|

首次诊断返回 `blocked`，退出码为 9，并明确记录 `write_request_sent=false`。

## 5. 对“控制台已显示权限”的解释

应用信息中的权限列表可以证明权限已被应用配置或申请，但不能单独证明权限已按当前调用身份授予租户。导入器以租户授权状态接口的 `grant_status` 和 `scope_type` 作为执行门禁：

- `scope_type=tenant` 才能用于当前 `tenant_access_token` 调用。
- `scope_type=user` 需要用户访问令牌，不能替代应用身份权限。
- 资源节点授权与 API Scope 必须同时满足，二者相互独立。

## 6. 解除门禁条件

1. 在飞书开放平台将 `wiki:node:retrieve` 和 `wiki:node:create` 授予应用身份。
2. 如权限变更需要版本发布和管理员审批，完成发布与审批。
3. 重新运行 `diagnose`；五项能力必须全部返回 `pass`。
4. 再运行只读 `preflight`，确认授权父节点和同名冲突检查通过。
5. 只有上述门禁全部通过后，才允许显式运行真实导入。

## 7. 安全边界

- 报告不包含 App Secret、访问令牌、完整节点 Token、完整飞书链接或正文内容。
- 导入器不申请或使用节点删除、节点移动权限。
- 权限不足时在任何写请求前失败，避免依赖飞书写接口返回错误来试探权限。
- 当前结论不代表批量导入、生产索引或生产检索已经可用。
