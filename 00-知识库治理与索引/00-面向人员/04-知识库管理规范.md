# 知识库管理规范

## 治理角色

|角色|职责|
|---|---|
|知识治理负责人|批准公司级规范和重大调整，协调跨空间争议|
|知识库总管理员|维护空间架构、机器 Schema、受控字典和权威来源注册表|
|空间管理员|管理本空间目录、权限、巡检和负责人交接|
|文档负责人|对内容准确性、适用范围、更新和废弃负责|
|内容审批人|批准文档正式发布并成为业务依据|
|安全审核人|审批机密级、限制级内容及例外 AI 权限|
|AI或检索平台管理员|执行索引准入、权限同步、失效清理和评测|

## 当前运行阶段

当前仅进行治理验证，尚未启用生产索引。

- 允许验证目录结构、机器 Schema、受控字典、模板、人员职责和准入规则。
- 可使用不包含真实敏感信息的样例元数据进行校验，但样例不得登记为公司权威事实。
- 禁止将真实文档写入生产向量索引、关键词索引或知识图谱。
- 禁止 Agent 将本项目内容作为公司业务事实回答依据，也不允许用于模型训练。
- 系统与平台字典、保留期限字典在本阶段可以保持为空；进入 AI 检索试点前必须重新评审并补齐适用值。

## 权威来源分工

- 飞书知识库负责公司正文、文档级元数据值、实际权限、审批和页面版本记录。
- Git 负责机器 Schema、受控字典定义、准入规则、目录稳定 ID、权威来源注册表、发布清单和自动化代码。
- Git 中的正文文件只用于首次创建种子或脱敏备份；飞书页面创建并回填真实标识后，正文权威转移到飞书。
- 同步程序不得用 Git 正文副本覆盖已移交飞书的页面，也不得用索引副本反向修改飞书或 Git 权威源。
- 访问判断以飞书实时 ACL 为最终否决条件；AI 准入还必须同时满足 Git 治理规则。

## 响应要求

- 人员离职或转岗后 1 个工作日内完成管理员、文档负责人和访问权限交接。
- 发现错误的正式知识后立即暂停 Agent 引用，并在 2 个工作日内完成修订、废弃或升级处理。
- 权限收紧、敏感信息误入库等事件立即阻断访问，并按安全事件流程处理。

## 规范和字典变更

1. 变更申请必须说明原因、影响范围、迁移方式和生效时间。
2. 通用治理字段由知识库总管理员维护，重大调整由知识治理负责人批准。
3. 业务域、系统平台、业务主题和权威来源由对应业务负责人提出并确认。
4. 字典值废弃时保留旧编码和替代关系，不直接删除历史值。
5. 变更完成后同步更新模板、校验规则和受影响的正式文档。
