# 千里智行·公司知识库结构设计与管理指南（V2）

> 本指南是公司知识库的治理入口，只保留整体设计、责任边界和规范索引。字段定义、操作细则及 AI 控制规则以所引用文件为准。
>
> 修订日期：2026-07-10

## 一、建设目标

建立统一、可信、可检索、可追溯、可治理的公司知识体系，同时服务员工检索和经授权的 AI Agent。知识库保存权威源文档；向量索引、查询缓存和自动摘要属于可重建的运行数据，不作为权威来源。

## 二、设计原则

1. `00-知识库治理与索引`作为公司级治理入口，由专业人员维护；各中心或部门保留自己的业务责任空间。
2. 空间按管理责任划分，跨空间检索依赖结构化元数据，不复制文档。
3. 同一主题只保留一份权威文档，其他位置使用链接引用。
4. 正式文档必须有负责人、审批人、适用范围、权威状态、有效状态和安全等级。
5. 公共知识默认只读或可评论，编辑权限遵循最小必要原则。
6. 原始隐私、轨迹、财务明细、密钥证书等高敏感数据不得进入通用知识库。
7. AI Agent 默认只使用当前用户有权限访问的正式、有效且获准引用的内容。
8. 知识质量必须通过复审、纠错和检索评测持续验证。

## 三、知识空间

|知识空间|定位|默认访问原则|
|---|---|---|
|00-知识库治理与索引|公司级知识治理规范、机器控制文件、索引与评测规则|专业维护团队管理；全员按需阅读人员规范|
|01-公司公共知识库|公司级公共信息|公共目录全员只读；受限目录按需授权|
|02-产品与技术管理中心知识库|产品、研发、架构、接口和技术方案|中心可读或评论，维护人编辑|
|03-运营管理中心知识库|运营策略、资产、调度、安全流程和用户运营|中心可读或评论，维护人编辑|
|04-政企合作中心知识库|准入、法规、政企合作和申报材料|中心可读或评论，敏感内容单独授权|
|05-职能部门知识库|财务、人力、总办等职能信息|部门内访问，公共制度另行发布|
|06-产业发展部知识库|产业研究、合作、业务拓展和生态建设|部门可读或评论，维护人编辑|
|07-体验与研究中心知识库|用户研究、设计、前瞻研究和测试评估|中心可读或评论，维护人编辑|
|08-跨部门协作空间|专项项目、联席会议和公司级协作|项目期授权，结束后归档和移交|

各空间的目录结构见[公司知识库空间与目录蓝图](./02-公司知识库空间与目录蓝图.md)，机器路径、稳定 ID 和索引策略以[知识库机器蓝图](../01-面向AI/01-knowledge-structure.yaml)为准。蓝图只定义信息架构，不表示相应业务文件已经存在。

## 五、当前落地范围

本项目只落地知识库治理规范、机器控制文件、空白模板和开放 Agent Skills，不创建各中心的实际业务文档，也不填写未经业务负责人确认的业务域、系统平台、权威来源或评测问题。

以下内容暂不在本指南中展开：

- 企业搜索、向量库和 Agent 平台的技术选型及部署实现。
- 独立 AI 语料中心或独立 Robotaxi 业务域知识空间。
- 自动化巡检和自动同步工具的具体实现。
