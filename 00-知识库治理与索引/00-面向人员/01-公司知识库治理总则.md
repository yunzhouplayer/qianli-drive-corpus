# 公司知识库治理总则

> 本总则是公司知识库的人员治理入口，规定建设目标、治理原则、权威边界、角色责任和运行边界。字段定义及机器控制规则以文中引用的 Git 控制文件为准。
>
> 当前运行模式：治理验证（`governance_validation`）；生产索引关闭（`production_index_enabled=false`）。

## 一、建设目标

建立统一、可信、可检索、可追溯、可治理的公司知识体系，同时服务员工检索和经授权的 AI Agent。知识库保存权威源文档；向量索引、查询缓存和自动摘要属于可重建的运行数据，不作为权威来源。

## 二、治理原则

1. `00-知识库治理与索引` 是公司级治理入口，由专业人员维护；各中心或部门保留自己的业务责任空间。
2. 空间按管理责任划分，跨空间检索依赖结构化元数据，不复制文档。
3. 同一主题只保留一份权威文档，其他位置使用链接引用。
4. 正式文档必须有负责人、审批人、适用范围、权威状态、有效状态和安全等级。
5. 公共知识默认只读或可评论，编辑权限遵循最小必要原则。
6. 原始隐私、轨迹、财务明细、密钥证书等高敏感数据不得进入通用知识库。
7. AI Agent 默认只使用当前用户有权限访问的正式、有效且获准引用的内容。
8. 知识质量必须通过复审、纠错和检索评测持续验证。

## 三、权威来源与同步边界

公司知识正文与机器治理规则分别使用唯一权威来源，禁止“最后写入者胜出”的双向覆盖：

|对象|唯一权威来源|处理原则|
|---|---|---|
|公司业务正文、人员侧治理正文、标题、文档版本和文档级元数据值|飞书知识库|在飞书评审、编辑、发布、回退和归档；Git 中的治理正文仅作为受控变更提案和发布种子|
|空间、目录、成员和文档实际访问权限|飞书实时 ACL|Git 只定义权限原则和期望结构，不复制成员权限表|
|元数据 Schema、受控字典定义、准入规则、稳定 ID、发布清单和自动化代码|Git|通过提交和评审维护，不由飞书页面反向覆盖|
|主题与权威文档的机器映射|Git 权威来源注册表|条目必须引用真实飞书文档稳定 ID 和业务审批依据；动态标题、负责人、状态和时间从飞书读取|
|索引、缓存、自动摘要、审计和运行状态|可重建的 `.runtime/` 数据|不提交 Git，不成为公司事实来源，不反向修改飞书或 Git 权威源|

治理说明发布遵循“Git 校验 → 飞书只读三方比较 → 管理员确认 → 显式写入 → 回读验证”。飞书自上次同步后有人工作修改时必须停止并人工合并。AI 使用文档时必须同时满足飞书正文正式有效、当前用户可访问且 Git 治理规则允许；任一侧拒绝即拒绝，飞书 ACL 是访问判断的最终否决条件。

## 四、治理角色与责任

|角色|职责|
|---|---|
|知识治理负责人|批准公司级规范和重大调整，协调跨空间争议|
|知识库总管理员|维护空间架构、机器 Schema、受控字典和权威来源注册表|
|空间管理员|管理本空间目录、权限、巡检和负责人交接|
|文档负责人|对内容准确性、适用范围、更新和废弃负责|
|内容审批人|批准文档正式发布并成为业务依据|
|安全审核人|审批机密级、限制级内容及例外 AI 权限|
|AI 或检索平台管理员|执行索引准入、权限同步、失效清理和评测|

人员暂以飞书通讯录姓名作为标识，实际成员身份和权限由飞书管理；出现同名人员时，机器控制文件必须改用飞书用户 ID。

## 五、当前运行边界

当前只进行治理验证：

- 允许验证目录结构、机器 Schema、受控字典、模板、人员职责、准入规则和不包含真实敏感信息的样例元数据。
- 样例不得登记为公司权威事实。
- 禁止将真实文档写入生产向量索引、关键词索引或知识图谱。
- 禁止 Agent 将本项目内容作为公司业务事实回答依据，也不允许用于模型训练。
- 系统与平台字典、保留期限字典可保持为空；进入 AI 检索试点前必须重新评审并补齐适用值。

本项目只落地治理规范、机器控制文件、空白模板和开放 Agent Skills；不创建各中心实际业务文档，不填写未经业务负责人确认的业务域、系统平台、权威来源或评测问题，不在本阶段建设生产索引、向量库或本地 AI 服务。

## 六、响应与变更要求

- 人员离职或转岗后 1 个工作日内完成管理员、文档负责人和访问权限交接。
- 发现错误的正式知识后立即暂停 Agent 引用，并在 2 个工作日内完成修订、废弃或升级处理。
- 权限收紧、敏感信息误入库等事件立即阻断访问，并按安全事件流程处理。
- 规范或字典变更必须说明原因、影响范围、迁移方式和生效时间。
- 通用治理字段由知识库总管理员维护，重大调整由知识治理负责人批准。
- 业务域、系统平台、业务主题和权威来源由对应业务负责人提出并确认。
- 字典值废弃时保留旧编码和替代关系，不直接删除历史值；完成后同步更新模板、校验规则和受影响文档。

## 附录：通用术语与缩写

|术语或缩写|含义|
|---|---|
|AI Agent|人工智能代理；在授权范围内检索、处理或生成结果的软件主体|
|ACL|Access Control List，访问控制列表；飞书实际权限是访问判断的最终依据|
|Schema|结构化数据的字段、类型、约束和校验规则|
|SOP|Standard Operating Procedure，标准操作程序|
|PRD|Product Requirements Document，产品需求文档|
|FAQ|Frequently Asked Questions，常见问题与回答|
|CI/CD|持续集成与持续交付或部署|
|SDK|Software Development Kit，软件开发工具包|
|OKR|Objectives and Key Results，目标与关键结果|
|HR|Human Resources，人力资源|
|Robotaxi|自动驾驶出租车及其配套出行运营体系|

本文未定义的内部术语以受控字典为准；缩写首次出现在其他正式文档时仍应给出中文名称和英文全称。
