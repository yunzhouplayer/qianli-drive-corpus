# 知识入库准备

## 运行时兼容与输入

- 遵循开放 Agent Skills 目录格式，不假设具体 Agent 品牌、调用前缀、文件工具或对话框架。
- 使用当前运行时提供的等价读取、解析、搜索和编辑能力；不支持某种文件格式时明确阻塞原因。
- `agents/openai.yaml` 仅是 OpenAI/Codex 可选界面适配器，其他 Agent 可以忽略。
- 接受以下输入：待处理文档路径或正文、知识库项目根目录（可自动定位）、操作方式 `analyze`/`propose`/`edit`，以及用户已经确认的责任或审批信息。
- 默认操作方式为 `propose`。没有明确的编辑授权时，只提供候选内容和修改方案。
- 不依赖先前对话中的隐含信息；跨 Agent 交接只使用源文件、治理文件和结构化交接产物。

## 基本边界

- 将输入文件整理到“可提交独立审查”的状态，不宣布“准入通过”或“已经入库”。
- 将用户提供的事实、从正文推断的候选值、尚待确认的信息分开标识。
- 不编造负责人、审批人、主题ID、文档ID、源链接、权限、业务域、系统平台或保留规则。
- 不自行将权威状态改为 `formal`，不自行放开任何 AI 权限，不更新权威来源注册表或语料清单。
- 发现隐私、密钥、轨迹、财务明细等禁止原始入库内容时立即停止扩散，给出删除、脱敏或转存专业系统的建议。

## 开始前

1. 读取[治理文件定位说明](./references/01-governance-files.md)。
2. 从当前工作区或目标文件向上定位项目根目录及 `00-知识库治理与索引`。
3. 按定位说明读取最小必要规则，并只提取目标空间、目录和字典值；不要完整输出机器蓝图。
4. 读取 `03-index-admission-rules.yaml`，记录当前 `operating_mode` 和 `production_index_enabled`。
5. 无法定位治理文件时停止准备并向用户索取项目根目录，不使用通用经验替代公司规则。

## 工作流

### 1. 读取文件

- 对 Markdown、文本和 YAML 直接读取。
- 对 Word、PDF、表格或图片使用对应的文档读取能力，并保留页码、工作表或附件定位。
- 无法可靠提取正文、表格或图片结论时标记为阻塞，不猜测缺失内容。
- 用户只要求检查时不修改原文件；用户明确要求修改时，保留原格式和现有有效内容。

### 2. 判断是否适合进入通用知识库

- 确认内容是可复用知识，而不是群聊、临时草稿、运行日志或原始业务数据。
- 搜索是否已存在同主题权威文档；存在时优先更新或引用，不创建重复权威副本。
- 判断内容应进入责任空间、协作空间、归档目录还是继续留在专业系统。
- 对禁止原始入库内容输出 `不适合入库`，不得通过改写标题绕过安全要求。

### 3. 形成候选元数据

- 以元数据 Schema 为唯一字段来源，以受控字典和机器蓝图为唯一取值来源；使用 YAML 解析器定向查询，不把整份控制文件加载到输出中。
- 同时展示机器编码和中文名称，例如 `testing_quality（测试与质量）`。
- 对系统生成字段标记“平台生成”，不要人为生成看似真实的ID或时间。
- 将字段标记为以下状态之一：
  - `已确认`：用户或权威来源明确提供。
  - `候选`：可从正文推断，必须由负责人确认。
  - `待确认`：没有足够依据。
  - `不适用`：Schema 允许不填写且本文确实不涉及。
- 当前处于治理验证模式时，将三个 AI 权限保持为 `false`。
- 受控字典为空时保留待确认项，不创建自由标签或临时编码。

### 4. 检查并完善正文

- 按 AI 友好写作规范检查目的、适用范围、不适用范围、核心结论、前置条件、异常处理、验收标准、关联文档和修订记录。
- 优先补足会导致误用的边界，再优化措辞和排版。
- 将事实、判断、建议和待确认结论明确分开。
- 将只存在于截图、扫描件或附件中的关键规则转成可检索文字，同时保留来源定位。
- 不为追求格式完整而添加无依据的业务内容。

### 5. 提交用户确认并修改

- 先列出拟修改内容和待确认字段。
- 仅在用户要求修改文件时实施修改；保持改动聚焦，不改变与入库无关的内容。
- 修改后再次核对标题、正文、元数据候选值和安全边界是否一致。
- 将整理后的文件交给 `review-knowledge-admission` 独立审查，不把本技能的结论作为审查证据。
- 运行时支持技能调用时按技能名发起交接；不支持时输出标准交接 YAML，交由其他 Agent 或人员继续处理。

## 输出与交接契约

默认同时提供简短人员摘要和结构化 YAML。结构化结果遵循[准备结果 Schema](./references/02-preparation-result-schema.yaml)；可写文件时保存为与源文件同目录的 `<源文件名>.knowledge-preparation.yaml`，不可写时返回 YAML 代码块。

人员摘要按以下顺序输出：

1. `准备状态`：`needs_input（需补充）`、`ready_for_review（可提交审查）`或`not_eligible（不适合入库）`。
2. `建议归属`：空间、目录及其稳定ID；无法确认时写明原因。
3. `元数据候选表`：字段、候选值、中文含义、确认状态、依据。
4. `内容与安全缺口`：按阻塞项、必须修改、建议优化排序。
5. `已实施修改`：仅列实际改动；未修改时明确说明。
6. `待负责人确认`：用可直接回答的问题列出，不一次追问无关信息。
7. `审查交接`：给出提交给审查 Agent 所需的源文件、候选元数据和准备结果位置。

不得使用“准入通过”“已批准”“已入库”等表述。
