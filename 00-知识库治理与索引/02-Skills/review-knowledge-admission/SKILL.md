# 知识入库审查

## 运行时兼容与输入

- 遵循开放 Agent Skills 目录格式，不假设具体 Agent 品牌、调用前缀或审批界面。
- `agents/openai.yaml` 仅是 OpenAI/Codex 可选界面适配器，其他 Agent 可以忽略。
- 要求输入：原始待审文件、与其对应的结构化候选元数据、知识库项目根目录；准备结果 YAML 可选，管理员身份和审批证据按场景提供。
- 不依赖准备 Agent 的对话上下文。即使收到准备结果，也必须重新读取原文件和当前治理规则。
- 使用当前运行时提供的等价文件和结构化数据工具；无法执行外部命令时不得省略机器规则检查。

## 审查原则

- 从原始文件和当前治理规则重新检查，不继承准备 Skill 的通过结论。
- 区分 `通过`、`不通过`和`阻塞`：缺少审批或业务事实属于阻塞，不用推断补齐。
- 文档负责人、内容审批人、安全审核人和管理员的确认不可由 AI 代替。
- 不通过时只输出整改项；未获得管理员明确确认时不修改源知识库或控制文件。
- 任何时候都不得降低安全等级、扩大 ACL 或放开 AI 权限以换取通过。

## 开始前

1. 读取[准入审查清单](./references/01-admission-checklist.md)。
2. 定位当前项目的 `00-知识库治理与索引`；找不到时停止并询问用户。
3. 读取原始待审文件、候选元数据和必要附件定位。
4. 读取当前机器蓝图、元数据 Schema、受控字典、索引准入规则和安全规范。
5. 记录 `operating_mode` 与 `production_index_enabled`，不得使用历史状态。

## 独立审查流程

### 1. 检查输入完整性

- 确认文件可读取且正文、表格、图片和附件没有关键内容缺失。
- 要求提供结构化候选元数据；没有时判定为阻塞并转交 `prepare-knowledge-document` 或输出所缺字段。
- 确认候选元数据与被审文件是一一对应关系，不审查无法定位来源的复制内容。

### 2. 执行机器校验

运行环境具有 Ruby 2.6+ 时，优先执行随技能提供的确定性校验器：

```bash
ruby <技能根目录>/scripts/validate_metadata.rb \
  --metadata <候选元数据.yaml> \
  --governance-root <项目根目录>
```

元数据嵌在文档或飞书属性中时，按原值提取到临时 YAML 后运行；不得在提取过程中补造字段。

运行环境没有 Ruby 时，使用任意兼容 JSON Schema Draft 2020-12 的校验器读取当前元数据 Schema，并按准入清单完成目录和受控字典交叉校验。记录所用校验器和版本；不能执行等价检查时判定为阻塞，不能直接通过。

机器校验至少覆盖：

- 基础必填字段、类型、枚举和条件必填字段。
- 空间ID、目录ID及二者归属关系。
- 文档类型、业务域、系统平台、来源系统、保留期限和安全等级受控值。
- 权威状态、有效状态、ACL 和 AI 权限组合。
- 当前治理模式是否允许生产索引。

脚本通过不代表正文、安全和审批已经通过。

### 3. 执行内容与安全审查

- 检查单一主题、目的、适用边界、不适用边界、规则或结论、异常处理、验收标准和来源定位。
- 检查标题、正文和元数据中的版本、范围、状态及责任人是否一致。
- 检查是否存在重复权威来源、过期内容或无法解释的冲突。
- 检查禁止原始入库内容、不可逆脱敏证据和权限最小化。
- 机密级或例外 AI 权限缺少安全审批时判定为阻塞。

### 4. 形成结论

- 任一规则不满足：`不通过`。
- 规则本身满足但缺少业务、审批、安全或管理员确认：`阻塞`。
- 机器、内容、安全和责任审批全部满足：`可提交管理员入库`。
- `operating_mode=governance_validation` 或 `production_index_enabled=false` 时，最高结论只能是 `治理验证通过`，不得声称真实入库或进入生产索引。

## 管理员入库交接

只有在结论允许且管理员明确确认后，按顺序引导：

1. 核对管理员是否登记在机器蓝图或公司级治理角色中。
2. 在飞书知识库选择已审查的目标空间和目录，设置最小必要 ACL。
3. 写入最终元数据；平台生成文档ID、创建时间和更新时间。
4. 由内容审批人设置正式和有效状态；需要安全审批时先完成安全审批。
5. 获得真实源链接后更新元数据中的 `source_url`，不得生成虚假链接。
6. 文档被确认为某主题唯一权威来源时，在业务负责人批准后更新 `05-authority-sources.yaml`。
7. 重新运行审查并保存最终报告或操作证据。

`06-corpus-manifest.yaml` 必须由索引流程生成，不得由管理员或任何 Agent 手工添加文档。生产索引关闭时必须保持为空。

## 输出与交接契约

默认同时提供简短人员摘要和结构化 YAML。结构化结果遵循[审查结果 Schema](./references/02-admission-review-result-schema.yaml)；可写文件时保存为 `<源文件名>.knowledge-admission-review.yaml`，不可写时返回 YAML 代码块。

1. `审查结论`：`failed（不通过）`、`blocked（阻塞）`、`ready_for_admin（可提交管理员入库）`或`governance_validated（治理验证通过）`。
2. `运行模式`：当前模式、生产索引开关及其影响。
3. `检查结果`：规则ID、结果、证据位置、问题和整改要求。
4. `阻塞审批`：负责人、审批人、安全审核人或管理员待确认事项。
5. `管理员操作清单`：仅在达到交接条件时输出。
6. `控制文件更新`：说明允许更新、禁止更新和实际更新的文件。
7. `复核结果`：入库动作完成后再次检查的结论。

没有管理员明确确认时，不执行第 6 项中的任何实际修改。
