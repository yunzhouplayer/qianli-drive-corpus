# 飞书治理树受控导入设计

## 1. 目标与边界

将当前 `qianli-drive-Corpus` 工作树的目录层级和可读文件导入已授权的无敏感飞书知识库测试节点下，用于验证飞书的目录、权限和变更记录能力。导入不开启生产索引，不登记生产语料，不改写授权父节点正文或其他子树。

## 2. 映射规则

- 在授权父节点下创建唯一受控根节点 `qianli-drive-Corpus`。
- 每个本地目录映射为一个 `docx` 知识库节点，保留两位序号和原始显示名称。
- `.gitkeep` 只证明目录应存在，不生成飞书文件页。
- 普通文件使用完整文件名作为节点标题；`README.md` 保留 README 导航语义，不改名为中文标题。
- Markdown 转换为标题、段落、列表、引用和代码块；YAML、Ruby、`.gitignore` 和其他文本控制文件以代码块保真。
- 页面首块写入机器受控标记，只包含相对路径、对象类型、SHA-256 和协议版本，不包含密钥或访问令牌。

## 3. 安全与幂等

- 导入集合来自当前工作树，显式排除 `.git`、`.DS_Store`、`.obsidian`、`.runtime`、环境变量文件和私钥容器。
- 正式请求前运行敏感信息路径扫描和内容扫描；命中时停止导入，只输出文件路径和规则类型。
- 本地状态写入 `00-知识库治理与索引/.runtime/feishu-import-state.json`，该目录已被 Git 忽略。
- 创建前分页读取父节点子项。若发现同名但无本地受控记录的节点，停止而不接管。
- 每成功创建一个节点就原子写入状态；中断后只校验并续传已知节点，不重复创建。
- 已受控文件变更时，先在原页追加并读回新块，完整匹配后才删除旧块范围；中断时保留旧版本或可识别的新旧并存状态，不会无验证覆盖。
- 不自动删除飞书节点。任何回滚删除必须依据状态表生成单独清单并由管理员再次确认。

## 4. 执行阶段

1. `plan`：本地扫描、敏感信息门禁、节点和块数估算，不访问飞书。
2. `preflight`：认证、解析授权父节点、分页读取子节点，不写入。
3. `apply`：先创建受控根节点作为金丝雀，读回确认后再按深度顺序创建目录和文件页。
4. `verify`：重新枚举受控子树，核对父子关系、标题、对象类型、首块标记和文件哈希。

## 5. 限流与失败处理

- 知识库节点请求不超过每秒 1 次，低于官方每分钟 100 次上限。
- 文档编辑请求不超过每秒 2 次，低于官方单应用和单文档每秒 3 次上限。
- 块创建每批最多 50 个；对 HTTP 429 或限流错误执行带抖动的指数退避。
- 权限、资源不存在、响应非 JSON、标记不匹配或同名冲突均是立即停止错误。

## 6. 验收条件

- 本地模拟覆盖首次导入、中断续传、同名冲突、限流重试和读回核对。
- 实际导入后飞书受控子树与本地计划的目录/文件节点数相等，不包含 `.gitkeep`。
- 每个文件页的受控标记路径和 SHA-256 与本地快照一致。
- 授权父节点原正文不变，非受控同级节点不变，生产索引开关仍为 `false`。
