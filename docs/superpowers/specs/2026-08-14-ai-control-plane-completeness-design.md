# 面向本地 AI 的知识控制面补全设计

## 1. 目标

在不补写业务正文、不启用生产索引、不改变飞书与 Git 权威边界的前提下，补齐本地 AI 使用公司知识库前所需的机器入口、索引策略、检索契约、ACL 上下文、审计格式和自动校验。

完成后，本仓库应能够回答以下问题：

1. AI 启动时必须读取哪些控制文件，顺序和优先级是什么；
2. 哪些文档允许进入索引，如何分块、更新、删除和回滚；
3. 本地 AI 以什么身份查询，返回什么结构，如何引用和拒答；
4. 如何记录准入、同步、查询、权限拒绝和评测结果；
5. 如何用一条本地命令发现配置缺失、Schema 漂移和跨文件引用错误。

当前仍保持：

- `operating_mode=governance_validation`；
- `production_index_enabled=false`；
- 飞书正文、权限和飞书版本记录以飞书为权威；
- Git 中的 Schema、字典、控制规则和工具脚本以 Git 为权威；
- 运行状态、凭证、缓存、索引和查询日志不得提交 Git。

## 2. 范围

### 2.1 本次实施

- 修正 `01-面向AI/README.md` 的文件清单漂移，并增加 AI 启动顺序和状态说明；
- 新增 AI 控制清单，作为机器启动入口；
- 为权威来源清单、语料清单、评测用例及新增控制文件提供 Schema；
- 新增检索运行契约，定义身份、ACL、查询、结果、引用和错误码；
- 新增索引策略，定义稳定分块、混合检索、更新删除和版本回滚要求；
- 新增运行审计事件 Schema；
- 新增统一控制面校验器和回归测试；
- 新增离线评测结果校验器，使权限负例、引用和拒答指标可以机器检查。

### 2.2 本次不实施

- 不补充具体业务文档、权威来源条目或真实评测问题；
- 不连接生产向量库、Embedding、重排模型或 MCP 服务；
- 不读取或修改飞书正文和权限；
- 不实现飞书正文反向覆盖 Git 的双向同步；
- 不把任何员工身份、查询日志、Token、密钥或运行态文件写入仓库。

## 3. 方案选择

采用“声明式控制文件 + 独立 Schema + 轻量校验脚本”的方案。

对比其他方案：

- 只扩写 README：成本最低，但本地 AI 无法可靠解析，也不能阻止配置漂移；不采用。
- 直接建设完整 RAG/MCP 服务：可运行性最高，但会越过当前治理验证阶段，并提前绑定技术栈；本次不采用。
- 声明式控制面：先冻结接口、权限和索引行为，再由后续实现适配不同本地 AI；与当前阶段最匹配。

## 4. 文件设计

### 4.1 启动入口

新增 `11-ai-control-manifest.yaml`，内容包括：

- 控制面版本、当前运行模式和生产索引开关；
- 必需控制文件的稳定 ID、路径、Schema、加载阶段和优先级；
- 冲突时的权威顺序；
- 缺文件、Schema 不兼容、未知字段和交叉引用失效时的 fail-closed 行为；
- Git 控制面与 `.runtime/` 运行态的边界。

AI 读取顺序固定为：启动清单 → 结构和字典 → 元数据与准入 → 权威来源和语料范围 → 索引策略 → 检索契约 → 评测和审计。

### 4.2 检索运行契约

新增 `12-retrieval-runtime-contract.yaml`，定义：

- 调用方必须提供的用户、组织、群组和会话身份上下文；
- 查询文本、过滤条件、返回数量和追踪 ID；
- 文档、分块、来源版本、引用定位和权限判定结果；
- 检索前候选过滤、读取前二次鉴权和回答前引用检查；
- `permission_denied`、`no_evidence`、`source_stale`、`control_invalid`、`service_unavailable` 等稳定错误码；
- 不得通过错误信息泄露未授权文档的存在性。

契约只冻结接口，不绑定 MCP、HTTP 或具体本地 AI 产品。后续适配器必须映射到同一契约。

### 4.3 索引策略

新增 `13-indexing-policy.yaml`，定义：

- 基于文档 ID、来源版本和分块序号生成稳定 chunk ID；
- 标题层级优先、最大 Token、重叠范围及不可拆分块规则；
- 表格、图片、附件和无法解析内容的处理边界；
- 内容哈希、幂等写入、事件去重、失败重试和死信要求；
- 更新、归档、删除、tombstone 和权限变更传播；
- 关键词与向量混合召回、重排、阈值和无证据拒答；
- 索引 generation、配置版本、评测门禁和回滚条件。

治理验证模式下，这些字段用于验证契约完整性，不触发真实索引构建。

### 4.4 Schema

新增以下 Schema：

- `schemas/04-authority-sources-schema.yaml`；
- `schemas/05-corpus-manifest-schema.yaml`；
- `schemas/06-evaluation-case-schema.yaml`；
- `schemas/07-ai-control-manifest-schema.yaml`；
- `schemas/08-retrieval-runtime-contract-schema.yaml`；
- `schemas/09-indexing-policy-schema.yaml`；
- `schemas/10-runtime-audit-event-schema.yaml`；
- `schemas/11-evaluation-result-schema.yaml`。

Schema 使用 JSON Schema Draft 2020-12，业务字段提供中文 `description`，核心对象默认拒绝未知字段。现有 `05`、`06`、`07` 文件增加 `$schema`、版本和责任字段，但继续保持业务条目为空。

### 4.5 审计与评测

运行审计事件覆盖：

- 控制面加载；
- 索引准入决定；
- 同步或删除任务；
- ACL 判定；
- 查询、召回与回答；
- 评测执行和回滚决定。

审计记录只定义格式和最小字段，不把真实记录提交 Git。敏感身份使用不可逆主体引用，不记录查询原文时必须记录脱敏摘要或哈希。

离线评测器接收 `07-evaluation-cases.yaml` 和独立结果 JSON，检查：

- 用例与结果是否一一对应；
- 允许来源、引用和回答状态是否一致；
- 权限负例是否零泄露；
- 无证据问题是否正确拒答；
- 结果是否记录控制面版本和索引 generation。

空评测集在治理验证模式下返回“有效但未执行”，不得声称检索质量通过。

## 5. 校验流程

新增 `scripts/validate_ai_controls.rb`，负责：

1. 检查启动清单列出的必需文件全部存在；
2. 检查 YAML/JSON 可解析、版本和顶层必填字段完整；
3. 检查 Schema 引用可定位；
4. 检查稳定 ID、文件路径和控制文件优先级唯一；
5. 检查语料、权威来源、评测用例、字典与结构蓝图之间的引用；
6. 检查治理验证模式与生产索引开关保持一致；
7. 检查 README 文件表与实际受控文件数量和路径一致；
8. 发现错误时非零退出并提供稳定错误码。

现有结构校验器继续负责目录树，不将其职责并入新脚本。

新增 `scripts/test_validate_ai_controls.rb` 和 `scripts/test_evaluate_retrieval.rb`，覆盖正常配置、缺文件、重复 ID、失效 Schema、越权结果、无引用回答和空评测集。

## 6. 错误与安全策略

- 所有控制面加载失败默认拒绝索引和查询；
- 未识别的 Schema 主版本不得降级忽略；
- ACL 缺失、过期或无法判断时按无权限处理；
- 未授权结果的错误信息不得包含标题、摘要、命中数、路径或存在性；
- 来源版本过期时不得以缓存内容回答；
- 无有效引用时只能拒答或明确返回无证据状态；
- 运行脚本只读取仓库和用户显式提供的离线结果，不访问飞书或外部服务。

## 7. 验收标准

实施完成后必须满足：

- AI README 文件表、启动顺序和实际文件一致；
- 所有新增 YAML 和 Schema 可解析；
- 现有结构、元数据、飞书导入和飞书退役测试继续通过；
- 新控制面校验器对当前仓库返回通过；
- 每类关键错误至少有一个失败测试；
- 空业务清单不会被误判为已有业务事实或检索质量达标；
- 仓库不出现密钥、Token、真实查询日志、索引文件或缓存；
- Git 工作区只包含本设计范围内的文件变化。

## 8. 后续边界

本次补全后，项目达到“AI 控制面契约完整、治理验证可执行”的状态。下一阶段才建设飞书只读增量同步、实际索引后端、本地 AI 的 MCP/HTTP 适配器、身份提供方接入和真实检索评测。在真实运行证据完成前，不得把本次结果描述为生产 RAG 已可用。
