# 飞书知识库单节点只读烟测设计

## 1. 结论

采用 B 方案：在不启用生产索引、不读取敏感业务内容、不执行任何飞书写操作的前提下，使用一个无敏感信息的测试知识库节点验证真实的飞书知识库读取能力。

本轮只回答三个问题：

1. 应用身份是否能读取被明确授权的测试节点及其必要元数据。
2. 应用身份是否会被拒绝读取未授权节点。
3. 节点更新时间、文档元数据和可获取的权限信息能否为后续治理提供足够证据。

应用认证已经通过，但认证成功不代表知识库节点或文档资源已经授权。本轮烟测通过前，不得宣称“飞书知识库已接入”。

## 2. 当前基线

- 项目运行模式保持 `governance_validation`。
- `production_index_enabled=false`，生产索引全局关闭。
- 飞书企业自建应用已经成功获取 `tenant_access_token`，令牌有效期实测为 7200 秒。
- App Secret 保存在 macOS 钥匙串服务 `qianli-feishu-smoke` 中，不进入仓库、日志或对话。
- 仓库尚无生产连接器、权限同步服务、事件订阅程序或运行索引。

## 3. 范围

### 3.1 本轮包含

- 获取并缓存本次进程使用的 `tenant_access_token`。
- 读取一个已授权、无敏感信息的测试知识库节点。
- 读取该节点关联文档的必要元数据，但不读取正文内容。
- 在飞书接口实际支持的范围内获取节点所有者、更新时间、资源类型和权限相关信息。
- 使用一个未授权节点进行反向验证，确认资源授权能够阻断读取。
- 输出脱敏烟测结果和可追溯的字段级证据。

### 3.2 本轮不包含

- 创建、移动、修改、归档或删除飞书节点和文档。
- 批量遍历知识空间、批量读取文档或下载附件。
- 读取测试文档正文。
- 建立向量索引、检索服务或 Agent 公司知识回答能力。
- 修改 `05-authority-sources.yaml` 或 `06-corpus-manifest.yaml`。
- 订阅事件、处理回调或承诺完整逐次变更审计。
- 使用用户访问令牌模拟员工权限。

## 4. 前置条件

执行前必须同时满足：

1. 飞书开放平台中的应用版本已发布或在当前租户内可用。
2. 应用只申请完成本轮验证所必需的当前官方只读权限；具体权限名称在实施时以飞书官方权限列表为准，并记录核验日期。
3. 测试知识库节点不包含个人信息、业务秘密、轨迹数据、密钥或其他敏感内容。
4. 应用已被实际授予该测试空间或节点的读取权。API 权限范围与具体资源授权必须分别确认。
5. 准备一个应用未获授权的对照节点，只提供节点标识，不扩大其权限。
6. 两个节点标识通过本地安全输入提供，不写入 Git；烟测输出仅保留不可用于访问资源的脱敏标识。

任一前置条件不满足时，烟测停止，不通过增加权限或扩大资源范围来规避。

## 5. 组件边界

烟测工具拆为四个独立单元：

|单元|职责|输入|输出|
|---|---|---|---|
|凭证读取|从 macOS 钥匙串临时读取 App Secret|固定 AppID、钥匙串服务名|进程内 Secret|
|令牌获取|调用飞书认证接口获取应用令牌|AppID、App Secret|进程内 Token、有效期|
|只读探测|调用节点、文档元数据及权限相关只读接口|Token、测试节点标识|原始临时响应|
|结果脱敏|过滤密钥、Token、完整节点标识、成员明细和非必要正文|原始临时响应|结构化烟测报告|

各单元不得把 Secret、Token 或完整资源标识传入命令行参数、持久日志或仓库文件。所有原始响应使用权限为 `600` 的临时文件，并在进程退出时清理。

## 6. 数据流

1. 从钥匙串读取 Secret，仅保存在当前进程变量中。
2. 换取 `tenant_access_token`，只记录 HTTP 状态、飞书错误码、有效期和令牌存在性。
3. 对已授权节点执行节点信息读取。
4. 若节点返回关联文档标识，则只读取文档元数据，不读取正文。
5. 若当前只读权限允许，则读取权限设置或协作者的非敏感摘要；不在报告中保存人员明细。
6. 对未授权节点执行同类请求，验证拒绝结果。
7. 将结果归一化为通过、失败或阻塞，并清理所有原始临时文件与进程变量。

## 7. 输出契约

烟测报告只允许包含：

- 执行时间、运行模式和测试阶段。
- 每个接口的 HTTP 状态、飞书错误码与脱敏消息。
- 节点是否存在、资源类型是否识别、元数据是否完整。
- 所有者字段、更新时间字段、权限摘要是否可获取；不记录成员名单。
- 已授权节点是否读取成功。
- 未授权节点是否被拒绝。
- 临时文件是否清理、Secret 和 Token 是否未出现在输出中。
- 结论、阻塞原因和下一步建议。

节点标识只保留短哈希或末尾四位，不能输出完整 Token、完整 URL 或可复用访问标识。

## 8. 错误处理

|情况|处理方式|结论|
|---|---|---|
|凭证无效|停止后续请求，不显示凭证|失败|
|缺少 API 权限|记录缺失的只读能力，不自动申请更大权限|阻塞|
|资源未授权|核对空间或节点授权，不提升为写权限|阻塞或反向测试通过|
|节点标识错误|停止该节点测试，要求重新提供正确标识|阻塞|
|接口限流或网络错误|有限次数重试；仍失败则保留脱敏错误|阻塞|
|返回意外正文或成员明细|报告生成前丢弃，不持久化|安全失败|
|临时文件清理失败|立即报告并人工清理|安全失败|

## 9. 测试矩阵

|用例|预期结果|
|---|---|
|认证接口使用正确凭证|成功获得进程内 Token，输出中没有 Token|
|读取已授权节点|成功返回节点基本信息|
|读取关联文档元数据|成功返回资源类型及更新时间等必要字段，正文未被读取|
|读取权限相关信息|在已批准只读权限范围内返回摘要；不支持时明确标记能力缺口|
|读取未授权节点|被飞书权限机制拒绝|
|缺少节点标识|在调用飞书节点接口前失败|
|响应内容扫描|Secret、Token、完整节点标识和正文均无命中|
|运行后清理检查|原始响应临时文件不存在|

## 10. 验收门禁

只有以下条件全部满足，P0 才判定为通过：

1. 已授权节点读取成功。
2. 未授权节点读取被拒绝。
3. 至少能够读取节点标识摘要、资源类型和更新时间等治理所需基本字段。
4. 全程没有写接口调用、正文读取、批量遍历或生产索引行为。
5. Secret、Token、完整资源标识和正文没有进入仓库或报告。
6. 原始临时响应已清理。

即使全部通过，结论也只能是“单节点只读接入验证通过”，不能声称权限同步、完整变更审计、生产检索或 Agent 检索已经可用。

## 11. 后续决策

- 若 P0 通过，进入单文档治理试点，补齐系统平台、保留期限、权威来源和评测用例。
- 若节点读取通过但权限信息不足，单独评估飞书权限接口或管理员导出证据，不扩大本轮范围。
- 若更新时间与版本信息不足以满足变更追溯要求，再单独设计事件订阅 PoC；事件订阅不属于本规格。
- 只有治理试点、ACL 证据、变更失效处理和安全评测全部通过，并获得明确生产批准后，才允许提出生产连接器设计。

## 12. 实施审批点

规格审阅通过后，实施前由用户提供：

- 一个已授权的无敏感测试知识库节点标识；
- 一个未授权的对照节点标识；
- 应用只读权限和资源授权已配置完成的确认。

上述信息仅用于本地一次性烟测，不写入仓库。
