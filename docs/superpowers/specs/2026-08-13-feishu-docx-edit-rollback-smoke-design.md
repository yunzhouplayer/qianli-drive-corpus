# 飞书新版文档编辑与回滚烟测设计

## 1. 结论

采用方案 A：在已经完成只读验证的无敏感测试文档末尾新增一个独立文本块，读取确认写入成功后立即删除该文本块，并验证文档根块的子块序列恢复到写入前状态。

本轮只验证应用身份是否具备该测试文档的真实编辑能力。测试不修改现有文本块，不创建子文档，不移动节点，不读取或输出现有正文，不作用于未授权对照节点。

## 2. 测试标记

新增文本块内容固定为：

```text
飞书 API 编辑权限烟测标记（验证完成后自动删除）
```

该标记只存在于验证窗口内。无论验证是否通过，只要新增操作成功，流程都必须进入回滚分支。

## 3. 前置门禁

执行前必须同时满足：

1. 目标仍为此前已验证的无敏感测试节点，链接从 macOS 钥匙串读取。
2. 节点解析出的对象类型为 `docx`；其他文档类型停止测试。
3. 应用已申请并发布 `docx:document` 权限。仅有 `docx:document:write_only` 不执行本测试，因为删除回滚接口不接受该权限作为充分条件。
4. 应用已被授予目标文档的实际编辑权限。
5. 当前运行模式保持 `governance_validation`，生产索引保持关闭。
6. 用户已经明确批准本次临时新增与删除操作。
7. 从开始写入到回滚完成的短暂测试窗口内，不安排人员或其他自动化同时编辑该测试文档。

任一门禁不满足时，只报告阻塞，不通过扩大权限、改用其他节点或保留测试内容来规避。

## 4. 使用接口

|步骤|方法与接口|用途|
|---|---|---|
|解析节点|`GET /open-apis/wiki/v2/spaces/get_node`|取得测试节点对应的 `docx` 文档对象标识|
|读取文档信息|`GET /open-apis/docx/v1/documents/:document_id`|取得当前文档版本号|
|读取根块|`GET /open-apis/docx/v1/documents/:document_id/blocks/:document_id`|取得根块子块 ID 有序列表|
|新增标记|`POST /open-apis/docx/v1/documents/:document_id/blocks/:document_id/children`|在根块末尾创建一个文本块|
|验证标记|`GET /open-apis/docx/v1/documents/:document_id/blocks/:block_id`|核对新增块内容和父块关系|
|删除标记|`DELETE /open-apis/docx/v1/documents/:document_id/blocks/:document_id/children/batch_delete`|按已确认索引删除本次新增块|

所有写请求都携带独立 `client_token` 作为幂等键，并使用已读取的明确文档版本号，不使用无条件覆盖语义。

## 5. 正常流程

1. 从钥匙串读取 App Secret 和已授权测试节点链接，仅保留在当前进程内。
2. 获取应用访问令牌并解析节点，确认对象类型为 `docx`。
3. 读取文档当前版本以及根块子块 ID 列表，计算列表摘要和原始子块数量 `N`；不读取现有子块正文。
4. 使用当前版本号，在根块末尾创建一个文本块；记录接口返回的新增块 ID 和新版本号。
5. 重新读取根块，确认：
   - 子块数量为 `N + 1`；
   - 新增块 ID 出现在根块子块列表中；
   - 除新增块外，原有子块 ID 的顺序保持不变。
6. 单独读取新增块，确认其父块为文档根块、块类型为文本且内容与测试标记完全一致。
7. 再次读取文档当前版本，并在删除前重新获取根块子块列表。
8. 只有在新增块 ID 仍能被唯一定位、其他原有子块顺序未发生冲突时，才以该块当前索引执行左闭右开的单块删除。
9. 删除后再次读取根块，确认子块 ID 有序列表与写入前完全一致。
10. 清理进程变量和临时响应，输出脱敏结果。

## 6. 并发与误删保护

- 删除目标不根据“最后一个块”猜测，而是根据创建响应返回的唯一块 ID 定位。
- 删除前重新读取根块并获取最新文档版本；删除请求绑定该版本号。
- 测试窗口内禁止人工并发编辑；发现根块或版本出现非本次操作能够解释的变化时停止自动删除。
- 如果新增块消失、出现多次、父块不符或无法唯一定位，停止自动删除，不尝试其他索引。
- 如果原有子块顺序发生变化，只在仍能唯一确认新增块且版本校验通过时删除该块；否则停止并进入人工清理提示。
- 不删除、更新或移动任何原有块。
- 接口限流时不盲目重放写请求；仅使用相同幂等键重试同一操作。

## 7. 失败与回滚

|失败阶段|处理|
|---|---|
|认证、节点解析或前置读取失败|停止，不发送写请求|
|新增接口被拒绝|记录权限或 API scope 缺口，停止|
|新增成功但读取验证失败|使用创建响应的块 ID进入受控回滚；不得再次创建|
|删除前发生版本冲突|重新读取一次并重新判断；仍有冲突则停止自动删除|
|删除接口失败|不执行其他写操作；明确提示用户在测试页面删除固定标记文本|
|删除后恢复校验失败|标记为安全失败，保留前后子块摘要和数量，不输出正文|

自动回滚失败时，人工恢复方式只有一项：在测试页面中删除内容完全等于固定测试标记的独立段落。不得删除相邻内容。

## 8. 输出与脱敏

报告只允许包含：

- 认证、节点解析、读取、新增、验证、删除和恢复校验的 HTTP 状态及飞书错误码。
- 写入前后文档版本号是否递增。
- 写入前、写入后和回滚后的子块数量。
- 原有子块有序列表摘要是否一致。
- 测试标记是否匹配、新增块是否已删除。
- 是否发送了创建与删除请求，以及回滚是否完成。

报告不得包含 App Secret、访问令牌、完整节点链接、完整节点或文档 Token、完整块 ID、现有正文、标题、所有者或人员标识。资源与区块只使用不可逆短哈希引用。

## 9. 验收标准

全部满足时，编辑烟测才判定为通过：

1. 新增接口返回成功，文档版本递增。
2. 新增文本块可被读取，内容与固定标记一致。
3. 删除接口返回成功，文档版本再次递增。
4. 回滚后根块子块 ID 有序列表与写入前完全一致。
5. 原有块没有被删除、更新或移动。
6. Secret、Token、块 ID 和现有正文没有进入仓库或报告。
7. 临时响应全部清理。

通过后的最强结论只能是“指定测试文档的应用身份编辑与回滚验证通过”。不能据此声称批量写入、业务文档自动维护、生产同步或用户级编辑权限已经可用。
